# ADR-007: Upgrade to Spring Boot 4.1 and Java 21

- **Context:** The project was built on Spring Boot 3.2.4 and Java 17. Free support for Spring Boot 3.2 ended in December 2024, and paid extended support in December 2025, so the framework under the api and the worker no longer received security fixes. Its pinned library versions had also fallen behind: Flyway 9.22 predated PostgreSQL 16, and Testcontainers 1.19.7 used a Docker API version that newer Docker Engines refuse, which failed CI on GitHub's runners. Both needed manual version overrides. Java 17 is supported until October 2027.
- **Decision:** Move to Spring Boot 4.1.2 and Java 21. That brings Spring Framework 7, Jackson 3, Hibernate 7.4, Flyway 12.4, Testcontainers 2.0 and JUnit 6, all at the versions Spring Boot manages, so the manual overrides are gone. Java 21 rather than 25: every library here has run on it for years, it is supported until 2029, and 25 can follow as a small, separate step.
- **Reason:** Spring Boot 4.1 is supported until July 2027 (2028 with paid extended support). Upgrading the framework and the language level together meant one migration instead of two.
- **What changed in the code:**
  - **Jackson 3:** imports from `tools.jackson.*` instead of `com.fasterxml.jackson.*`; `asText()` renamed to `asString()`; exceptions are unchecked, so two catch blocks went away and one became `JacksonException`. Annotations keep their old package.
  - **Starters:** `spring-boot-starter-webmvc` replaces `starter-web`, and Flyway needs `spring-boot-starter-flyway`.
  - **Testcontainers 2:** the module is `testcontainers-postgresql` and the container class is `org.testcontainers.postgresql.PostgreSQLContainer`.
  - **Build:** compiler and Surefire plugin versions pinned to Spring Boot's recommendations, because importing its dependency list doesn't manage plugins. Docker images and CI on Java 21.
- **Evidence it's safe:**
  - A throwaway project confirmed first that Hibernate 7.4 maps `jsonb` columns to Jackson 3's `JsonNode`, which `JobEntity` relies on, and that `@Immutable` still prevents writes on read.
  - All 179 tests pass, including one added to pin the timestamp format clients see.
  - Spring Boot's properties migrator reported no renamed or removed settings.
  - Flyway 12 validated the existing database history written by Flyway 9 and 10.
  - Every endpoint and job type behaved the same on the running stack.
  - A back-to-back throughput test showed no difference: a median of 3,350 jobs/s against 3,402 on the old version ([results](../../experiments/results/20261030T142910Z-throughput/)).
- **Consequence:** Developers and CI need JDK 21. Spring Boot 4.1's support ends in July 2027, so the next upgrade is due around then. Not adopted as part of this change: Java 21's virtual threads for the worker's handler threads. They suit IO jobs well but change runtime behavior, so they deserve their own measured experiment.
